# 安装与第一次运行

> 本文是**非官方 SeqKit GUI** 的简体中文文档。SeqKit GUI 是 [SeqKit](https://github.com/shenwei356/seqkit)（Wei Shen 开发的 MIT 许可序列工具包）的桌面图形前端；本项目与 SeqKit 项目无关，未获其认可，也不由其维护，不是 SeqKit 的官方图形界面。

## 1. 这个项目是什么

SeqKit GUI 是一个用 PySide6（Qt）编写的桌面图形界面，它把 SeqKit 命令行工具的 41 个子命令渲染成表单，帮你组装参数、启动 `seqkit` 进程并展示结果。

| 它做 | 它不做 |
| --- | --- |
| 列出全部子命令与参数，按类型渲染输入控件 | 不做任何序列计算：解析 FASTA/Q、统计、搜索、转换全部由 `seqkit` 完成 |
| 把界面上的勾选与填写转换成参数数组，用 `QProcess` 启动 `seqkit` | 不拼接 shell 命令字符串，因此文件名里的空格与引号不会改变命令含义 |
| 实时读取 `stdout` / `stderr`，把完整输出落盘 | 不修改、不重新分发 SeqKit 源码，也不自带 SeqKit 可执行文件 |

因此 **`seqkit` 可执行文件是运行任何命令的前提**：找不到它时界面仍可打开，但命令无法运行。

## 2. 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10/11 x64 —— 这是唯一经过实测的平台。macOS/Linux 的启动脚本与路径代码已写好，但未在真实机器上验证过 |
| Python | 3.10 及以上（`pyproject.toml` 里 `requires-python = ">=3.10"`） |
| 图形库 | PySide6 `>=6.6,<7`（`requirements.txt` 里唯一的运行时依赖） |
| SeqKit | 2.14.0 可执行文件，解压后约 28 MB（官方压缩包约 8.6 MB），需自行准备 |

seqkit 不随仓库分发：上游发布的是几十 MB 的二进制，受 SeqKit 自己的 MIT 声明约束（见 [`THIRD-PARTY-LICENSES.md`](../../THIRD-PARTY-LICENSES.md)），因此 `bin/` 被 `.gitignore` 忽略。

## 3. 安装

### 3.1 取得源码

把仓库克隆或解压到任意目录（下文用 `<项目目录>` 指代，例如 `D:\SeqKit-GUI`）。

### 3.2 安装 Python 依赖

```bat
cd /d <项目目录>
python -m pip install -r requirements.txt
```

`requirements.txt` 只包含运行所需的 PySide6；PyInstaller 与 pytest 作为可选开发工具以注释形式列在同一文件中，不需要运行本程序时可忽略。

### 3.3 准备 seqkit 可执行文件

任选一种方式：

| 方式 | 操作 | 适用场景 |
| --- | --- | --- |
| 官方发行包脚本（推荐） | `python tools/fetch_seqkit.py` | 能联网；脚本按当前系统/架构下载 SeqKit 2.14.0 官方发行包，解压出可执行文件放进 `bin/` |
| 手动放入 | 把 `seqkit.exe` 复制到 `<项目目录>\bin\` | 内网机器、离线环境 |
| 放在 PATH | 任意位置安装 seqkit，确保命令行里 `seqkit version` 可用 | 机器上已装过 seqkit |
| 在设置里指定 | 启动后点顶栏**设置**，在“SeqKit 可执行文件”里填完整路径，或点**自动检测**/**浏览**，再点**测试**确认能运行 | 想使用其他版本或其他位置的 seqkit |

`fetch_seqkit.py` 的常用参数：

| 参数 | 作用 |
| --- | --- |
| （无参数） | 下载 SeqKit 2.14.0 到 `bin\` |
| `--version 2.9.0` | 下载指定版本 |
| `--sha256 HEX` | 除上游随包发布的 `.md5.txt` 之外，再要求归档的 SHA-256 等于给定值 |
| `--force` | 覆盖 `bin\` 里已有的文件 |
| `--list` | 只列出脚本能取到的资源名以及本机对应的那一个，不联网 |
| `--timeout 60` | 每个网络请求的超时秒数（默认 30） |

该脚本只用 Python 标准库，未安装 PySide6 时也能运行。它会按上游随包发布的 `.md5.txt` 校验归档的 MD5，再检查解出来的可执行文件（拒绝 HTML 错误页、小于 1 MB 的文件、Windows 上不是 `MZ` 头的文件），最后写临时文件并用 `os.replace` 原子改名，所以网络异常时不会留下半个损坏的二进制。上游为每个平台发布的是 tar.gz（Windows 的是 `seqkit_windows_amd64.exe.tar.gz`，里面装着 `seqkit.exe`）。

程序按下面的顺序查找 seqkit，找到第一个可用的即停止：

| 顺序 | 位置 | 状态栏里显示的来源 |
| --- | --- | --- |
| 1 | “设置”中填写的路径（留空则跳过这一步） | `configured` |
| 2 | 程序旁的 `bin\` 目录（Windows 下依次尝试 `seqkit.exe`、`seqkit.cmd`、`seqkit.bat`、`seqkit`；源码运行与打包运行都指向同一个 `bin\`） | `bundled` |
| 3 | 系统 `PATH` | `path` |
| 4 | 仅 macOS：`/opt/homebrew/bin`、`/usr/local/bin` | `path` |

候选项必须是一个真实存在的文件，并且文件头是这台机器真能执行的镜像格式：Windows 要 `MZ`、Linux 要 `\x7fELF`、macOS 要 Mach-O 魔数。Windows 上 `.bat`/`.cmd`/`.com`/`.ps1`/`.vbs`/`.js`/`.lnk`/`.url` 这类脚本文件被直接拒绝（`QProcess` 与 `subprocess` 都无法把它们当程序启动），所以第 2 步列出的 `seqkit.cmd`、`seqkit.bat` 两个候选名虽然会被尝试，却总是过不了这道判定；非 Windows 平台额外要求 `os.access(path, os.X_OK)` 执行位，并允许 `#!` 开头的脚本。除**设置里由用户亲手选定**的那条之外，任何直接位于程序当前工作目录里的候选一律拒绝；`PATH` 里的空项与相对项被跳过，`shutil.which` 在 Windows 上优先命中的当前目录项也会被拒绝并继续逐项遍历 `PATH`。重复路径只判一次。这一整套判定的目的写在 `seqkit_gui/core/seqkit_locator.py` 的模块注释里：防止二进制种植劫持。

## 4. 启动

| 方式 | 命令 |
| --- | --- |
| Windows 启动脚本 | 双击 `<项目目录>\run.bat`，或在该目录下执行 `run.bat` |
| POSIX 启动脚本 | `./run.sh`（额外参数透传给程序；可用 `PYTHON=...` 指定解释器，未指定时优先用 `python3`） |
| 模块方式 | `python -m seqkit_gui` |

两个启动脚本都会检查解释器是否存在、在 `bin\seqkit(.exe)` 缺失时打印获取办法，然后**照常启动**——那段提示是信息性的，不会中止程序。macOS / Linux 与 Windows 用的是同一套源码。

窗口默认尺寸约 1320×860，左边是命令列表，右边上下分成参数表单与输出面板两块。标题为 `SeqKit GUI`。

## 5. 确认 seqkit 已被找到

界面上有三处报告查找结果：

| 位置 | 一切正常时应该看到 |
| --- | --- |
| 顶栏徽标 | `SeqKit 2.14.0`（悬停显示所用文件的完整路径） |
| 状态栏左侧 | 所用文件的完整路径 + 命中来源，例如 `D:\SeqKit-GUI\bin\seqkit.exe  (bundled)` |
| 顶栏徽标右侧 | 空白；出现琥珀色的**版本不匹配**徽标说明检测到的版本不是 2.14.0；徽标本身变成 `未找到 seqkit` 说明一个候选都没命中 |

版本徽标是实时探测的：内容来自对所用二进制执行 `seqkit version` 的输出。若解析出的版本号与参数表版本（2.14.0）不同，界面上会多出一枚警示徽标，悬停说明“参数可能不完全一致”。

手动指定路径：**设置 → SeqKit 可执行文件**，或 **工具 → 手动指定 seqkit 可执行文件**。把该字段留空即回到自动检测；**测试**按钮会对填进去的路径执行 `seqkit version`，结果显示版本字符串、`无法运行该文件` 或 `未找到 seqkit`。

## 6. 第一次运行：用 grep 提取一条序列

仓库自带测试数据 `<项目目录>\tests\data\short1.fa`，可以直接拿来跑第一次。

1. **选命令**：在左侧命令树的**搜索命令**分组里点击 `grep · 按 ID/name/序列/序列 motif 搜索序列，允许错配`（分组默认已展开）。也可以在顶部的“搜索命令”框里输入 `grep` 过滤（支持按命令名、中文名、英文说明、别名匹配）。
2. **加输入文件**：在**输入文件**区点**添加文件**并选中 `tests\data\short1.fa`；也可以把文件直接从资源管理器拖进窗口，或用**粘贴路径**把剪贴板里的路径逐行导入。
3. **填参数**：展开**命令参数**（标题右侧的 `16` 表示该命令有 16 个专属参数），
   - 勾选 `--pattern`（短选项 `-p`），在出现的多行框里输入 `seq1`；
   - 勾选 `--ignore-case`（短选项 `-i`）——布尔参数只有勾选框，勾选即传该开关。
   - **其余参数保持不勾选**：不勾选的参数不会出现在命令里，seqkit 使用它自己的默认值。
4. **运行**：点输出面板的**运行**按钮（或按 `Ctrl+R` / `Ctrl+Enter`）。
5. **看结果**：跑完后自动停在**结果**标签页，显示匹配到的记录；右下角状态形如 `完成 · 退出码 0 · 耗时 0.16s · 输出 52B`；切到**命令行**标签可以看到本次真正执行的命令：

```text
"D:\SeqKit-GUI\bin\seqkit.exe" grep --ignore-case --pattern seq1 -- "D:\SeqKit-GUI\tests\data\short1.fa"
```

那个独立的 `--` 是界面固定插入的选项终止符：位置输入文件永远排在它之后，这样一个以 `-` 开头的文件名不会被 seqkit 当成参数解析（见 `seqkit_gui/core/builder.py` 的 `TERMINATOR`）。

状态栏右下角会随表单内容实时预览这条命令，点**复制结果**可复制序列，点**复制完整命令**（`Ctrl+Shift+C`）可复制命令行到剪贴板，拿去终端复现。

## 7. 第二次运行：统计并把结果写成文件

1. 左侧选择 `stats · FASTA/Q 文件的简易统计`（别名 `stat`）。
2. **输入文件**里添加 `tests\data\short1.fa` 和 `tests\data\short2.fa`。
3. 展开**命令参数**，勾选 `--all`（`-a`）。
4. 展开**全局参数**，勾选 `--out-file`（`-o`），点**浏览**选一个输出路径，例如 `D:\tmp\stats.tsv`。
5. 运行。此时**结果**标签页为空、状态提示“运行成功，但没有标准输出内容”属正常现象——输出已被 seqkit 直接写进 `-o` 指定的文件。

> 提示：勾选 `--out-file` 后结果写入该文件而不经标准输出；不勾选它，结果才显示在**结果**标签页里，同时被完整保存到临时文件（**打开输出文件**/**保存结果**用的就是这份文件）。

## 9. 遇到问题时

先看这几条，完整排查清单见 [常见问题](faq.md)：

| 现象 | 处理 |
| --- | --- |
| 顶栏显示“未找到 seqkit” | 按 3.3 节任选一种方式提供可执行文件，然后在**设置**里点**自动检测** + **测试** |
| 点**运行**弹出“参数不完整” | 弹窗列出了缺失项，对应参数行的说明文字会变红；每个命令的必需参数见 [命令指南](command-guide.md) |
| 选 `scat` 后弹窗“必须设置其中之一：--find-only / --time-limit” | `scat` 对目录建立 fsnotify 监听器并循环，不给退出条件就永不返回，所以界面在创建子进程前就拒绝这次运行。勾 `--find-only`（拼接已有文件后退出）或 `--time-limit`（无活动超时后退出）；`--wait-pid` 不算退出条件 |
| 顶栏出现“版本不匹配” | 参数表按 SeqKit 2.14.0 生成，检测到的版本不同时个别参数可能有差异；可换用 2.14.0 或按提示重新生成参数表（见 [开发说明](development.md)） |
| 退出码非 0，**结果**标签是空的 | seqkit 把报错写在 stderr；切到**错误**标签看原话，**日志**标签里有同样的内容和完整命令行 |
| 输入文件留空后跑出一条空结果 | 界面不代理标准输入，留空时 seqkit 读到的是立即结束的标准输入；请至少添加一个文件 |
| 中文界面里有英文词 | 界面文字表 `seqkit_gui/i18n/zh_CN.json` 缺少该键时会回退英文 |

## 10. 已知限制

第一次运行前后值得知道的边界，完整清单见 [README 的“已知限制与诚实声明”](../../README.md#已知限制与诚实声明)：

- 只在 Windows x64 上人工实测过；macOS/Linux 有代码分支（`platform.system()` 判断、Darwin 专用查找前缀、`run.sh`、下载器的 `Darwin`/`Linux` 分支），但没人在这两个平台的桌面上打开过这个窗口，也没有对应的打包产物。
- 不代理标准输入，没有管道模式：输入必须是文件路径。子进程一启动就 `closeWriteChannel()`，不给输入文件的运行会以退出码 0 结束、结果为空。真正会停不下来的是 `scat`（fsnotify 目录监听），界面在运行前校验里就要求它带退出条件。
- 参数表绑定 seqkit 2.14.0，其他版本可能出现参数缺失或多出。
- `--threads` 在界面上显示的 `默认值: 4` 是参数表从 seqkit 2.14.0 的 `--help` 里记录下来的字面值，界面不会按本机 CPU 数重算它；上游的真实取值是 `min(NumCPU, 4)`，可被 `SEQKIT_THREADS` 覆盖（`seqkit/cmd/root.go:113-128`）。`genautocomplete --file` 的预填值是参数表保存的中性占位 `$HOME/.bash_completion.d/seqkit.sh`，界面把它展开成你这台机器上的家目录。
- 不重新分发 seqkit，需自行放入 `bin/` 或用 `tools/fetch_seqkit.py` 下载。
- **命令行**标签、**复制完整命令**、**日志**标签与状态栏里的内容都带 seqkit 与输入输出文件的绝对路径、工作目录和临时文件路径，其中通常含本机用户名；外发前先清理。
- 界面预览有行数与文本块上限，完整输出在系统临时目录的 `seqkit-gui-*.out` 里；非 UTF-8 字节会被替换显示。
- 同一时间只能运行一条命令。
